# 《岔路》分类视觉设计

日期：2026-09-22

## 问题

《岔路》的卡片目前只有分类、标题和简介。数据与渲染代码都没有图片字段，因此线上并非“图片加载失败”，而是从未实现视觉内容。

## 设计方向

为六个领域各提供一张抽象视觉：数字档案、博物馆、长文、地图、交互作品、代码实验。同一领域的入口共用一张图，让访客先感到门后的材料性质，同时避免把《岔路》变成十八张互相争夺注意力的作品墙。

视觉沿用“雨后城市与电子地图”的语言：雾蓝灰、柏油黑、旧地图蓝、苔藓绿和少量信号橙。图像由橙子生成，不含文字、商标、人物和具体机构建筑，也不声称是链接目标的实景。

六类意象：

- 数字档案：扫描光、纸张断面、微缩胶片和索引格。
- 博物馆：标本抽屉、玻璃边缘、物件轮廓和标签痕迹。
- 长文：纸页层次、边注、阅读灯形成的狭长光域。
- 地图：等高线、旧地图折痕、坐标网格和未完成路径。
- 交互作品：节点、轨迹、输入反馈和偏离中心的信号。
- 代码实验：像素网格、着色器噪声、几何场与一处运行中的橙色脉冲。

## 资产与渲染

- 使用一次图像生成得到严格的 3×2 无文字视觉图板，再机械裁成六张正方形 WebP，避免六次生成造成风格漂移。
- 资产保存到 `public/images/trails/`；页面以 4:3 视窗裁切展示，并压缩到适合网页加载的体积。
- 在 `src/scripts/trails.ts` 中维护分类到图片路径的固定映射；`trails.json` 保持入口数据本身，不重复存储同一分类的图片地址。
- 卡片顶部新增固定比例的 `<img>`。图像只提供气氛，不承载入口信息，因此使用空 `alt`；分类、标题和简介继续承担可访问的信息表达。
- 图片加载失败时隐藏图像区域，文字卡片仍可使用。
- 不增加外部图片请求，不调整现有 Content Security Policy，不收集访问数据。

## 版式

- 桌面端维持三列，每张图位于卡片顶部，文字区继续使用现有留白与层级。
- 360px 手机端维持单列，图片宽度随卡片变化。
- 不增加自动动画；鼠标悬停只改变链接颜色，避免让六类抽象图变成动态装饰。

## 验证

- 为《岔路》浏览器测试增加断言：每张随机卡片都有本站图片，图片完成加载，且三张卡片仍来自三个不同分类。
- 运行 `npm run verify:publish`，覆盖隐私扫描、Astro 检查、静态构建、移动端宽度、键盘与浏览器测试。
- 线上检查 `/path/` 的三张随机卡片及六张静态资产返回成功；构建或部署失败时保留旧版本。
